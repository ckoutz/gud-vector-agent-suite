# Public quote API — frontend contract

The public API backs client websites that render a customer-facing quote page
(first: `gudvector.com` at `<site_url>/q/<claim_token>`) and, for sites that
have opted in, collect payment through Stripe Checkout.

Every endpoint below is **unauthenticated** except by the values in the path —
the claim token for quotes, the publishable key for booking links. Nothing in a
response identifies the business internally, the owner, or any other customer:
no `business_id`, no database ids, no phone numbers. Unknown or invalid tokens
return a generic `404 {"detail": "not found"}`; claim tokens are never stored
in clear server-side (only a SHA-256 hash) and are looked up in constant time.

CORS: `GET`/`POST` only, for the set of configured business `site_url`s plus
`GVAS_PUBLIC_CORS_EXTRA_ORIGINS`. Client-site routes are rate-limited per
source IP.

## `GET /v1/quotes/{claim_token}`

Renders the quote. The first successful fetch marks the customer-facing status
`viewed` (idempotent — repeat fetches keep returning it).

```json
{
  "business": {
    "displayName": "Güd Vector",
    "siteUrl": "https://gudvector.com"
  },
  "quote": {
    "id": "gvq_0123456789abcdef0123456789abcdef",
    "status": "viewed",
    "customerName": "Jane Doe",
    "serviceAddress": "123 Main St, Walnut Creek, CA",
    "items": [
      {"description": "Mold inspection", "quantity": 1, "amountCents": 25000}
    ],
    "subtotalCents": 25000,
    "totalCents": 25000,
    "currency": "USD",
    "note": "Includes one air sample.",
    "createdAt": "2026-01-02T15:04:05Z",
    "approvedAt": "2026-01-02T15:10:00Z"
  }
}
```

- `quote.id` is an opaque public id (`gvq_…`) — never the row id; use it only
  for display and client-side reference.
- `quote.status` progresses `viewed` → `accepted` → `paid`, or to `declined`.
- `note` may be `null` when the owner left the quote note empty.
- `items[].amountCents` is the line total; `subtotalCents`/`totalCents` are the
  customer's amounts (total is what checkout collects).

Errors: `404` unknown token · `429` rate limited.

## `POST /v1/quotes/{claim_token}/accept`

Creates (or returns the existing) Stripe Checkout Session for the quote:

```json
{"checkoutUrl": "https://checkout.stripe.com/c/pay/cs_live_…"}
```

Redirect the browser to `checkoutUrl`. The session is `mode=payment`, currency
`usd`, with `success_url` = `<site_url>/q/<token>?paid=1` and `cancel_url` =
`<site_url>/q/<token>` — so the page should treat `?paid=1` as "payment is
being confirmed" and re-fetch the quote: the authoritative `paid` status
arrives via the Stripe webhook, usually within seconds.

Re-calling while an open session exists returns the same `checkoutUrl`, so a
double-click or retry is safe.

Errors: `404` unknown token · `409` quote is already `paid` or `declined` ·
`503` payments are not enabled on this deployment · `429` rate limited.

## `POST /v1/quotes/{claim_token}/decline`

```json
{"status": "declined"}
```

Errors: `404` unknown token · `409` quote is already `paid` · `429` rate
limited.

## `GET /v1/businesses/{public_key}/booking-link`

Returns publishable business details — used by the contact form's success
state to offer a booking link. `public_key` is generated by the
`gvas-configure-business` CLI and is safe to embed in the site bundle.

```json
{"calendlyUrl": "https://calendly.com/gudvector", "displayName": "Güd Vector"}
```

Errors: `404` unknown key or the business has no booking URL · `429` rate
limited.

## `POST /webhooks/stripe` (Stripe → GVAS, not for the frontend)

Subscribed events: `checkout.session.completed`,
`checkout.session.async_payment_succeeded`,
`checkout.session.async_payment_failed`. Signature-verified with
`Stripe-Signature` (5-minute tolerance); the first delivery of an event marks
the payment and the quote `paid` and enqueues an owner notice in the
conversation where the quote was approved. Replays are answered `200`
`{"status": "ignored"}` without redoing work.
